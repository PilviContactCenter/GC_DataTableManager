# Application review — 2026-10-10

GPT-6 Astra reviewed the consolidated Docker web app, its SDK contracts,
configuration, tests, and deployment files. Three GPT-6.1 Sol subagents fixed
and tested the findings in isolated worktrees. Astra then reviewed the
integrated changes and confirmed all eight findings were addressed.

| Finding | Priority | Resolution and regression coverage |
| --- | --- | --- |
| Old row handlers target a newly selected table | P1 | Clear rows/schema immediately, gate actions, bind mutations to loaded table identity; slow/failed switches and removed selections tested. |
| An old save closes a newer dialog | P2 | Capture dialog identity and ignore obsolete completions; cancellation, reopening, stale success/error, and duplicate submission tested. |
| Stale edits overwrite other editors | P2 | Compare a fresh row with the original before update/delete, retain drafts on conflict; changed rows and canceled checks tested. |
| Audit pages move their time window and mix ranges | P2 | Freeze query sessions, serialize controls, guard stale responses; insertion, range changes, close/reopen, retries, and duplicates tested. |
| Pagination silently stops at 10,000 rows | P2 | Follow pagination metadata and fail explicitly at a safety limit; 101 pages and limit rejection tested. |
| New-row forms ignore defaults | P2 | Initialize fields from schema defaults; submitted defaults and explicit false/zero/empty edits tested. |
| PKCE/storage, region retry, and equivalent group ID failures | P2 | Use a fresh in-memory verifier, validate each login attempt, compare UUIDs without case sensitivity; storage denial, invalid retries and Docker configuration tested. |
| Row dialog has no accessible name | P3 | Associate the dialog with its visible title; DOM assertion and browser accessibility state verified. |

Verification includes 38 passing Node regression tests, JavaScript syntax
checks, and browser checks against an isolated mock SDK. Browser checks covered
defaulted create, edit, native Escape/reopening, named dialogs, and two-page
audit history with before/after values. No production table data was changed
by those tests.

## Limits

Conflict detection uses a GET followed by PUT/DELETE. The SDK exposes no atomic
conditional row write, so another change between those requests can still race.
An already-sent write may complete after cancellation; refresh the table to see
its final state. Real-time audit history covers the previous 14 days. Mocked
login tests cover the PKCE contract; they do not authenticate as a live user.
